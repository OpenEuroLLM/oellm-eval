# v0.02: calibrated evaluation procedures

Select `--eval_version v0.02` when scheduling. The CLI continues to default to `v0.01` for backward compatibility: upgrading a source checkout must not silently change an existing campaign. The `v0.01` tag freezes the old executable source; the `v0.02` tag adds the calibrated procedures. The Python distribution's existing `0.1.0` version is separate from these benchmark protocol tags.

## Changes

| Family | v0.01 | v0.02 |
|---|---|---|
| GSM8K | Four train-set examples, ordinary Question/Answer prompt, 256-token adapter default, string matching | Fixed four-shot CoT, explicit greedy decoding, 1024 output tokens, numeric equality of the already-extracted number. Retain string scores; primary metric is `numeric_match,flexible-extract`. |
| SQuAD-v2 | Literal `unanswerable` can be scored as a nonempty answer | Map exactly that taught marker to the empty answer. Preserve prompts, examples and no-answer probabilities. |
| LiveCodeBench | Fence-only code extraction | Preserve all previously extracted candidates; otherwise accept one syntax-checked relaxed/unfinished fence or complete bare Python program. Same tests, repeated generations and installed grader. |
| HumanEval | 1024-token greedy instruction procedure, faulty completion-fence boundaries | 4096-token greedy instruction procedure and corrected boundaries; preserve full Python and Bash coverage. Existing avg@32 remains a separate entry point. |
| GPQA-Diamond | Evalchemy three-repeat instruction procedure | Calibrated harness zero-shot CoT with seeded shuffled options, 4096 output tokens and explicit-answer/boxed priority. One full 198-question pass, explicitly a different prompt/repetition protocol. |
| MATH500 | Model-view-dependent instruction template | Frozen Qwen3 template, explicit greedy decoding and `<\|im_end\|>` stopping, retaining the calibrated 32768-token output allowance. |

The scheduler maps original GSM8K, SQuAD-v2 and GPQA task names to explicit new task identities. Other task names and shot counts remain unchanged. The same changes apply to all evaluated models; no parser uses a reference answer to choose among candidate answers, repairs code, drops questions or awards correctness from syntax alone. The complete settings and template source identity are in [v0.02.json](v0.02.json). The Qwen3 template is reproduced from `Qwen/Qwen3-8B`, revision `b968826d9c46dd6066d109eabc6255188de91218`, under Apache-2.0; preserve that attribution when redistributing it.

## Scheduling and containers

Use the existing [JUPITER installation](../machines/jupiter/from-scratch.md), checking out this release for the control CLI. No new dependency installation or container rebuild is needed for these Python-level corrections when using the recorded complete evaluator image. The scheduler copies the reviewed runtime, parsers, task definitions and template into each submission's `protocol/` directory. It binds that snapshot read-only into the evaluation container and verifies its SHA-256 manifest before running. This works without a collaborator's home directory or the calibration workspace. Do not edit a submitted snapshot.

```bash
# Activate the dedicated evaluation control environment from the installation guide.
# Model/image/cache and scheduler settings must already be set as in that guide.
oellm-eval schedule-evals --eval_csv_path checkpoint-suite.csv \
  --model_backend vllm --data_parallel_size 4 --tensor_parallel_size 1 \
  --eval_version v0.02 --log_samples true --dry_run true
```

Inspect the rendered script and its `protocol/manifest.json`, perform the ordinary offline task/model checks, and submit once through the existing campaign scheduler. A full-suite run requires all normal datasets and code graders. The release does not start a new campaign, raise campaign budgets, or alter any already-running evaluation.

Use separate output roots for v0.01/v0.02 and keep the model checkpoint, data revision, context allowance and resources in the campaign manifest. The wrapper records resolved generation settings, prompt lengths, request counts and completion status in adjacent `*.protocol.json` receipts. `collect` retains `eval_version` and `protocol_variant`, and does not deduplicate results across them. Historical files without a manifest remain `unversioned`; audit their provenance before labelling them v0.01.

## Context and matched output budgets

The new wrapper refuses to truncate prompts or silently shrink the declared output allowance. Configure enough context for the entire prompt plus output, using validated RoPE extension where needed; allocation of a longer context is not evidence of model quality at that length. The default MATH500 calibration is a 32768-output reference procedure, not the separately requested 4k/16k comparison. For those comparisons, pass `--calibrated_output_tokens 4096` or `16384` to apply an explicit common HumanEval/MATH500 allowance; it is recorded as `output-4096` or `output-16384`. Use the same allowance across models, reserve prompt room above it, and label these results separately from the default calibration. Other benchmarks retain their declared budgets. Models that cannot execute a required context belong only in the compatible comparison.

GPQA's 4096 output also needs prompt room beyond a 4096 total context. Insufficient context stops before generation instead of reporting a corrupted score. Longer-output B1 runs require the existing prompt-length audit and minimum sufficient RoPE factor; do not change training checkpoints in place.

## Evidence and limitations

The integration replays all 1319 saved GSM8K numeric verdicts (1187 correct, 89.99%) and all 11873 SQuAD examples (43.62% → 66.47% F1, 2713 gains and zero losses). The installed-evaluator check loads complete datasets and matches all 198 GPQA prompts/options and all 500 MATH500 chat prompts against the calibration sources. Regression tests exercise actual rendered launchers, immutable snapshots, context rejection and version-separated collection. No new GPU generation was performed while cutting the release; the previous full-task calibration runs supply generation evidence, not proof of complete v0.02 checkpoint-suite reproduction.

GSM8K's improvement includes prompt/length changes, so B1 requires new generations; its Qwen gain cannot simply be added to historical B1 scores. GPQA's headline reference gap and full MATH's gap remain open. MATH500 is not full MATH. The LCB reference recovery used mixed historical grader-resource provenance, including a bounded per-answer memory overlay; this release changes extraction while retaining the installed grader. Preserve grader resource settings and failures in future comparisons. HumanEval's improved output allowance is not the sampled NVIDIA recipe; see [avg@32](../humaneval_avg32.md).

Source unit tests run with the existing control test dependencies. The real-runtime acceptance entry point is `tests/check_release_runtime.py`, run CPU-only inside the complete image with `--snapshot`, `--gsm-samples`, `--model-view` and `--gpqa-helper` pointing to frozen calibration evidence. It neither loads model weights nor executes generated code. The workspace's existing `reference_eval_gap_audit.py --squad-runtime-samples` separately verifies the SQuAD change against the installed scorer.
