# Greedy decoding compatibility

Full checkpoint 64000 testing found a decoding error in the pinned lm-eval-harness 0.4.12 adapter. When a request omits both temperature and do_sample, normalize_gen_kwargs infers do_sample=False but does not materialize temperature. The vLLM adapter then removes do_sample, so SamplingParams defaults to temperature=1. Tasks that explicitly supply greedy settings, such as GSM8K, MBPP and IFEval, are unaffected. Actual SQuAD2 requests contain only an until field even though the displayed task configuration lists greedy settings; inspect requests, not only configuration summaries.

The narrow harness-greedy-default.patch sets temperature=0 whenever normalized do_sample is False. Explicit non-greedy sampling is preserved. The source reconstruction and image provenance pin the corrected harness tree 445cac369f9989a227810560114be2aea498851d. Existing images do not change automatically: regenerate the continuation overlay with the updated helper, which accepts both known adapter versions and applies the same correction to the old image's adapter. Both reconstruction routes reproduce the seven tested overlay files byte-for-byte. The final adapter SHA256 is 7b17d9b1f9d567b7df0b6b47056257ffe46f2591bdc793f1d7f181d7c546b49e.

Validation: seven actual adapter/SamplingParams cases inside the pinned ARM vLLM 0.28 image pass. Full standard Dyck job 1752190_0 evaluates all 1,000 unchanged 10-shot inputs and scores 53.3%, versus 53.4% for HF and 36.8% with the faulty default. Independent sample aggregation and input/hash identity pass; elapsed 257 seconds. The complete reference suite is still running, including full reruns of the eight affected benchmark configurations. This is a decoding correctness fix, not a benchmark change or a reduction in task coverage. Initial faulty results must remain labelled invalid and must not be used for checkpoint comparisons.

The workspace report and reproducible campaign are in oellm_32B_loss-increase_debug/reports/full_reference_suite_2026-09-11.md in oellm-workflows. No image is rebuilt or overwritten by applying this source change. Rebuilding is explicit through the existing documented image workflow; existing-image users must regenerate and mount the corrected overlay.
